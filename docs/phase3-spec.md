# Phase 3 规格:外置记忆闭环(提醒 + 召回)

Phase 2 让猫能听懂并记住。Phase 3 让记住的东西**主动找回你**(提醒)和**被你找回来**(召回)。这两件事做完,"替你记"这条产品线才闭环。

## A. 本地通知提醒

### 为什么是本地通知
定时提醒的时刻在落库那一刻就已知,不需要服务器推送。本地通知离线可靠、零服务器成本、不依赖账号——与"capture 永不失败"的原则一致。远程推送留到 Phase 6 之后(跨设备场景)。

### iOS 通知上限:64 条 pending

系统硬限制:每 app 最多 64 条待触发的本地通知,超出的**静默丢弃**(又一个静默失败点)。所以不能"每条提醒注册一个通知"了事,必须滚动维护:

- core 提供 `pending_reminders(limit, now) -> Vec<Memory>`:未完成、未软删、`due_at > now`,按 due 升序取前 N 条。
- Swift 侧 `NotificationScheduler`:每次**记忆变更后**和**app 进入前台时**重新同步——取消全部已注册通知,按 core 返回的前 **56** 条重新注册(留 8 条余量给 Phase 4 的复习提醒)。
- 同步是幂等的全量重放,不做增量 diff——记忆量级(个人用户几百条)下重放成本可忽略,而增量同步的状态错配 bug 极难排查。
- **可观测性**:设置页显示"已排期提醒:N 条"。参照 Phase 2 的教训,静默截断必须有一个显式的观察点。

### 通知内容(猫的口吻,不是系统提示音)

- 标题:`🐱 该交电费啦`(猫 emoji + 提醒标题)
- 正文:原话 `raw_text`
- 分类 identifier `reminder`,带两个 action:**「记下了」**(标记完成 +1 小鱼干)和 **「等会儿」**(推迟 30 分钟,重新排期)。
- 点通知进 app 直接定位到那条记忆。

「等会儿」需要 core 增 `snooze_reminder(id, new_due_at, now)`。

### 权限
`UNUserNotificationCenter.requestAuthorization`。**不在启动时索要**——首次成功创建一条 reminder 之后再问,那时用户已经理解为什么需要通知,授权率显著更高。拒绝后:记忆照常保存,列表里正常显示,只是不弹通知;设置页给一个跳系统设置的入口。

## B. 问猫召回

### 数据流(隐私:只发命中的几条)

```
用户问"我把护照放哪了?"
  → core.search_for_recall(query, limit=8)   本地检索,不出设备
  → 命中的 8 条(仅这些)+ 问题 → Worker /v1/recall → LLM 组织答案
  → 猫用一句话回答,并附上引用的原始记忆卡片
```

**只有本地检索命中的条目会离开设备**,全量记忆永远不上传。答案下方列出被引用的记忆,用户能验证猫说的有没有依据。

### 本地检索(core)

`search_for_recall(query: String, limit: u32) -> Vec<Memory>`:
- SQLite FTS5 建 `memories_fts` 虚表(`raw_text`、`title`、`question`、`answer`),迁移里创建 + 触发器同步。
- 中文没有空格分词,FTS5 默认 tokenizer 会把整句当一个 token。**用 `unicode61` + 对中文按字切分**(把查询串成 `字1 AND 字2 ...`),或退回 LIKE。**实现前必须写测试验证中文能命中**——这是最容易想当然做错的地方。
- 排序:FTS rank 优先,同分按 updated_at 倒序。
- 检索不到就返回空,Worker 侧直接答"我没记过这个"。

### Worker `POST /v1/recall`

请求:`{ question, memories: [{id, kind, title, raw_text, created_at}] }`
响应:`{ answer: string, cited_ids: string[] }`

- 同样的鉴权 + 配额 + 8s 超时 + 降级。
- 降级行为**不同于 parse**:parse 失败可以静默(记忆已存),但召回失败用户正在等答案,必须**明确告知**:"猫有点困,先看看这些记忆吧" + 直接展示本地检索结果。宁可退化成朴素列表,也不能假装没事发生。
- system prompt 要求:只依据给定记忆回答,**没有依据就说不知道,不许编**;答案控制在两句内;返回引用到的 memory id。

### UI

记忆页顶部加搜索框(placeholder"问猫:护照放哪了?")。输入即本地检索实时过滤(零延迟);按回车才触发 LLM 召回。答案以猫的气泡形式出现在列表上方,下面跟着被引用的记忆卡片。

## 验收

1. 设一条 5 分钟后的提醒 → 锁屏收到猫口吻通知 → 点「记下了」→ app 里那条变完成、鱼干 +1。
2. 造 80 条未来提醒 → 设置页显示"已排期提醒:56 条",不崩不静默丢。
3. 问"我把护照放哪了" → 猫答出抽屉位置并引用那条记忆。
4. 问一个从没记过的事 → 猫明确说不知道,不编造。
5. 断网时问猫 → 显示本地检索结果 + "猫有点困"提示,不是空白或报错。
6. 拒绝通知权限 → capture 与列表完全正常,仅无通知。

## 不做(留后)
跨设备同步提醒、重复提醒(每天/每周)、基于位置的提醒、语音问答(召回先用文字输入)。
